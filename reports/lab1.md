# 功能
- 实现**sys_trace**追踪当前任务系统调用的历史信息
1. 如果 trace_request 为 0，则 id 应被视作 *const u8 ，表示读取当前任务 id 地址处一个字节的无符号整数值。此时应忽略 data 参数。返回值为 id 地址处的值。
2. 如果 trace_request 为 1，则 id 应被视作 *const u8 ，表示写入 data （作为 u8，即只考虑最低位的一个字节）到该用户程序 id 地址处。返回值应为0。
3. 如果 trace_request 为 2，表示查询当前任务调用编号为 id 的系统调用的次数，返回值为这个调用次数。**本次调用也计入统计** 。
4. 否则，忽略其他参数，返回值为 -1。


# 问答题
#### 深入理解 trap.S 中两个函数 __alltraps 和 __restore 的作用，并回答如下问题:
1. sp指向保存中断时CPU的栈帧，_restore一种从内核终端处理程序返回用户态，一种从 mret 等返回指令中恢复到先前的运行环境

2. sstatus：保存用户态的状态（包括中断使能等位）。sepc：保存异常发生前的程序计数器值。sscratch：保存用户态原始 sp。他们作用是用于恢复用户程序运行前的状态，使得 sret 能正确跳回用户态。

3. x2 是 sp，它通常在恢复过程中被特别处理。x4 是 tp（线程指针），可能在其他上下文中恢复，或当前上下文中不需要。

4. sp 被设置为 sscratch 中的值，即恢复用户态的栈指针。sscratch 也可能保存当前内核态的 sp，以备下次陷入时使用。

5. sret. sret 会从 sepc 中恢复 PC（程序计数器）；并根据 sstatus 中的 SPP 位决定跳回用户态或内核态；此外会恢复中断使能等重要状态。    

6. sp：恢复为用户态线程的栈指针；sscratch：保存当前内核态的 sp。

7. ecall 用于用户态程序请求操作系统服务；会触发陷入（trap）到内核态（S 态）。
